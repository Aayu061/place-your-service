## 4. Addressing VS Code Explorer Clutter

### Problem Analysis:
The user observed that VS Code displays:
- `dist/` (frontend compiled assets)
- `server/dist/` (backend compiled JavaScript, `.d.ts`, and `.map` files)
- `node_modules/` and `server/node_modules/`
- `.temp/`

These directories are **already git-ignored** in `.gitignore`. However, because `.vscode/settings.json` was absent, the VS Code editor UI displays them in the primary Explorer tree, making navigation cumbersome.

### Resolution:
1. Create `.vscode/settings.json` (explicitly permitted by `.gitignore` line 33: `!.vscode/settings.json`):
   - Configure `files.exclude` to hide compiled build directories (`dist/`, `server/dist/`, `supabase/.temp/`, `**/*.tsbuildinfo`).
   - Keep `node_modules` visible or collapsible as desired, or hide it from search indexing.
2. Add a `clean` script in root `package.json`:
   - `"clean": "node -e \"fs.rmSync('dist', { recursive: true, force: true }); fs.rmSync('server/dist', { recursive: true, force: true })\""`
   - This provides a cross-platform, dependency-free command to immediately wipe local build artifacts on demand.
